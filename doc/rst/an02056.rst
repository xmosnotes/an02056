AN02056: Board test procedure and code
======================================

When developing a new board it may be useful to run a set of test programs
on the board to check for basic functionality. This application note
contains a set of test programs and a python program that runs those
programs and a few additional tests.

In its simplest form, a single Python test procedure can be executed that
will perform a series of basic tests. The tests performed include:

* Establish that JTAG is connected up

* Establish that the chip is responsive

* Establish that hello world works

* Establish that the oscillator is set to the correct frequency

* Find the XSCOPE link

* Establish that XSCOPE works reliably

* Establish that the power supply can supply the peak rate

* Establish that the power supply can respond to a sudden change in load

* Identify the flash device and its properties

* Program the flash and execute the code

The source code for these tests is provided, allowing users to:

* Provide a board description to deal with different crystal
  frequencies etc

* Extend or modify the tests

* Add additional tests

The tests have been written for XCORE.AI. All except the power supply tests
will also work on XCORE-200. Before presenting each test, this document discusses how to
obtain the software and how to build it.

Downloading the test program
----------------------------

This section assumes that the `XMOS XTC Tools <https://www.xmos.com/software-tools/>`_ have been
downloaded and installed. The required version is specified in the accompanying ``README``.

Installation instructions can be found `here <https://xmos.com/xtc-install-guide>`_.

Special attention should be paid to the section on
`Installation of Required Third-Party Tools <https://www.xmos.com/documentation/XM-014363-PC/html/installation/install-configure/install-tools/install_prerequisites.html>`_.

The application is built using the `xcommon-cmake <https://www.xmos.com/file/xcommon-cmake-documentation/?version=latest>`_
build system, which is provided with the XTC tools and is based on `CMake <https://cmake.org/>`_.

The ``an02056`` software ZIP package should be downloaded and extracted to a chosen working
directory.

Running the test program
------------------------

The app note comes with a test program that runs all tests in sequence.
Assuming Python (> 3.7.7) and the XMOS tools are installed (see the
previous section), run the following Python script::

  python test.py

This runs a sequence of tests using the **pre-built binaries** found in the ``default_bin`` directory, and stops at the first failing test,
providing a log of outputs.

If successful, the test passes and no further action is required. If it fails,
information is provided on where and why the failure occurred.

Building the tests from source
------------------------------

All tests can be built from scratch and run individually allowing modifications to be made. This is
especially important for boards that, for example, use a
different input clock frequency, run at a higher frequency (800 MHz
parts), or have the boot flash on unusual pins.

Before building the system, the configuration file for
the board should be copied over each of the ``app_an02056_*/board.xn`` files. The default
``board.xn`` file assumes a 600 MHz XCORE.AI chip with a flash connected to
the standard pins. This file may be usable, but copying the board XN
file over the provided ``board.xn`` file will ensure that the XN file is
correct.

To configure the build, the following commands should be run from an XTC command prompt::

    cd an02056
    cmake -G "Unix Makefiles" -B build

All required dependencies are included in the software package. If any dependencies are missing,
they will be retrieved automatically during this step.

The application binaries should then be built using ``xmake``::

    xmake -j -C build

Binary artefacts (.xe files) will be generated in:

*  ``app_an02056_hello_world/bin`` for hello world

*  ``app_an02056_frequency/bin`` for the frequency test

*  ``app_an02056_xscope_discovery/bin`` for the xscope discovery test

*  ``app_an02056_xscope/bin`` for the xscope delivery test

*  ``app_an02056_power/bin/slope`` for the power supply test

*  ``app_an02056_power/bin/impulse`` for the load change test

*  ``app_an02056_flash/bin`` for the flash test

For subsequent builds, the ``cmake`` step may be omitted.
If ``CMakeLists.txt`` or other build files are modified, ``cmake`` will be re-run automatically
by ``xmake`` as needed.

These individually built binaries can be run manually using::
    
  xrun --io <path_to_binary>

or for xscope tests::

  xrun --xscope <path_to_binary>

.. important:: All the binaries are generated in the directories above; not in
   the ``default_bin`` directory where the python script ``test.py`` expects the binaries.
   Hence, after building, the binaries must either be run manually as shown
   below, or copied into the ``default_bin`` directory where they will
   be picked up by ``test.py``.


Chip responsiveness
-------------------

Chip responsiveness is tested by issuing this command::

  xrun -l

The output should be::

  Available XMOS Devices
  ----------------------

    ID    Name                  Adapter ID      Devices
    --    ----                  ----------      -------
    0     XMOS XTAG-4           42ADT6AB        XS3A[0]

Where the Adapter ID is an eight-character string. The test program expects
exactly one XTAG adapter.

Hello world
-----------

This program, predictably, prints "Hello world". It does so over JTAG.
Execute this program as follows::

  xrun --io app_an02056_hello_world/bin/app_an02056_hello_world.xe

The output should be::

  Hello world!

On error ``xrun`` may hang.

Frequency test
--------------

This program prints, 60 times, a message exactly one second apart.
The whole program should execute in exactly 60 seconds. The timings can be visually
checked by observing a wall clock
simultaneously ::

  xrun --io app_an02056_frequency/bin/app_an02056_frequency.xe

The output should be::

  00:00:00
  00:00:01
  00:00:02
  ...
  00:00:59
  
If the lines are not one second apart, then either the Oscillator frequency
in the XN file does not reflect the input frequency on XIN, or the
reference timer is not set correctly.

XSCOPE Discovery
----------------

This program, opens all the links, and checks which link receives a credit
token. It then prints the number of the link(s) with the credit token::

  xrun --xscope app_an02056_xscope_discovery/bin/app_an02056_xscope_discovery.xe

The output should be::

  XSCOPE on link 0

Where 0 is the number of the link. In most cases it is link 0 (the only
link that comes out on the QF60 packages).

XSCOPE
------

This program, prints "hello " followed by a number 1000 times.
It does so over XSCOPE so the numbers should be printed rapidly.
Execute this program as follows::

  xrun --xscope app_an02056_xscope/bin/app_an02056_xscope<number>.xe

Where <number> is replaced with the link number identified above.
The output should be::

  hello 0000
  hello 0001
  hello 0002
  ...
  hello 0999

There should be no gaps in the messages. A gap indicates that the host
computer is not fast enough to keep up with xscope; garbled output
indicates that the xscope link is electrically unstable. No output
indicates that the xscope link is not enabled properly. On error ``xrun``
may hang.

Power supply peak
-----------------

The power supply peak test runs a program that, on both tiles, executes VPU
instructions with alternating bit patterns. This puts a high demand on the
power supply. Execute this program as follows::

  xrun --io app_an02056_power/bin/slope/app_an02056_power_slope.xe

The output should be::

  PASS

Any other output indicates that the power supply is not keeping up with
demand. ``xrun`` will hang on any error.


Power supply load change
------------------------

The power supply load change test runs a program that, on both tiles, executes VPU
instructions with alternating bit patterns. It starts all threads
simultaneously causing a sudden load change on the power supply.
Execute this program as follows::

  xrun --io app_an02056_power/bin/impulse/app_an02056_power_impulse.xe

The output should be::

  PASS

Any other output indicates that the power supply cannot cope with a sudden
load change. ``xrun`` will hang on any error.


Flash ID
--------

The flash ID is read with the command::

  xflash --spi-command 0x9f 3 0 --target-file app_an02056_flash/board.xn
  

Flash SFDP
----------

The flash SFDP (Serial Flash Discovery Protocol) is read with the command::

  xflash --spi-command 0x5A 259 0 --target-file app_an02056_flash/board.xn
  
This produces the descriptor as specified in JEDEC Standard 216H.

Flash Program
-------------

This programs the Flash with the command::

  xflash app_an02056_flash/bin/app_an02056_flash.xe

And should end with a successful write. The application will then be run automatically and
it will write the word 0x5AA50FF0 into address 0xF0000 which is unused by the application.

.. code-block:: none

   Site 0 has finished successfully.        


Check core booted from flash
----------------------------

This test uses the debugger to attach to the target. This does not reset the chip
but instead breaks any currently running program allowing the state to be inspected.


The test performs the following commands in XGDB::

  attach
  p/x *(0xF0000)

The expected output is::

  $1 = 0x5aa50ff0
